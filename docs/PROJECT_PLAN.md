# خطة مشروع Kayan Ai

## 1. الرؤية
مساعد WhatsApp لكيان سوفت يساعد العملاء على فهم مجالات الشركة، ويستقبل استفسارات المشاريع ويجمع موجزًا واضحًا لمتطلبات العميل، مع إتاحة الإحالة البشرية للحالات التي تحتاج مراجعة. التجربة تبدأ على Sandbox.

## 2. معلومات المشروع المؤكدة
- النشاط: كيان سوفت (KAYAN SOFT)، شركة برمجيات وحلول رقمية، والسوق المرتبط بها اليمن.
- الموقع: https://kayan-soft.online
- نبرة المساعد: صنعانية ودودة وقريبة من العميل، من دون تكلف.
- **الخدمات المتاحة حاليًا حسب تأكيد المالك:** المواقع التعريفية، تطبيقات الويب ولوحات التحكم والمتاجر الإلكترونية وتطبيقات Android وiOS؛ الأنظمة الإدارية والمحاسبية المخصصة وإدارة المبيعات والمخزون والموارد البشرية والطلبات والعملاء؛ UI/UX وواجهات التطبيقات والمواقع؛ ربط الأنظمة عبر APIs وقواعد البيانات وتحسين الأداء والسرعة والتوافق مع الهواتف؛ مساعدين ووكلاء الذكاء الاصطناعي وأتمتة خدمة العملاء وربط النماذج بقواعد البيانات وحلول SaaS؛ التسويق الرقمي وإدارة حسابات التواصل والمحتوى والحملات الإعلانية وSEO والخطط التسويقية وتحليل الأداء والتسويق بالبريد؛ الشعارات والهويات والمنشورات والإعلانات والبنرات والموشن جرافيك؛ والحلول السحابية والبنية التقنية ونشر التطبيقات وإدارتها والخدمات الخلفية والاستضافة والمصادقة والتخزين والشبكات والصيانة والمراقبة.
- **سياسة التسعير المؤكدة:** الأسعار تُحدد حسب نطاق المشروع ومتطلباته؛ لا توجد قائمة أسعار ثابتة معتمدة للمساعد. يشرح المساعد العوامل المؤثرة في التكلفة ويجمع تفاصيل المشروع قبل عرض الإحالة لموظف لتقدير نهائي.
- لا تتوفر بعد أسعار مؤكدة أو ساعات دوام أو عنوان/مدينة أو بيانات اتصال موثقة أو وعود بمدة تنفيذ.

## 3. التقنية والقرارات الحالية
- قناة WhatsApp عبر Kapso، مع تشغيل المساعد في Workflow داخل Kapso.
- رقم WhatsApp Sandbox موجود، وWorkflow التجربة نشط على Sandbox فقط.
- النموذج الحالي: **GPT-4.1 mini**؛ استُعيد بعد تجربة Gemini، بناءً على أحدث توجيه من المالك.
- قائمة الخدمات الحالية وسياسة التسعير حسب النطاق مثبتتان بتأكيد المالك.
- **لا حاجة إلى خادم Vercel في المرحلة الحالية**: Kapso يستضيف الـWorkflow الحالي. يعاد تقييم Vercel إذا احتجنا Webhook مخصصًا، أو API، أو تكاملًا خارجيًا غير متاح مباشرة في Kapso.
- الأسرار لا تُخزن في GitHub. تحفظ في مخزن الأسرار للخدمة التي تحتاجها؛ وإذا أضيف خادم Vercel مستقبلًا فتستخدم متغيرات البيئة المحمية فيه، لا في الشيفرة أو مستودع Git.
- سجل النموذج والاستضافة: [قرار Gemini والاستضافة](DECISIONS/2026-10-16-gemini-and-hosting.md) مع ملاحظة الاستبدال الواردة فيه.

## 4. نطاق النسخة التجريبية
1. الترحيب بالعميل والرد باختصار بلهجة صنعانية طبيعية.
2. التعريف بمجالات كيان سوفت اعتمادًا على المعلومات الموثقة أعلاه.
3. فهم هدف العميل وجمع نوع الخدمة والمتطلبات الأساسية تدريجيًا.
4. عدم اختلاق أسعار أو ساعات عمل أو مواعيد أو مدد تنفيذ أو توفر خدمة.
5. الإحالة إلى موظف عند طلب العميل أو الحاجة إلى عرض سعر أو قرار فني/تجاري غير متاح.
6. عدم ربط رقم إنتاجي أو إرسال حملات أو إنشاء حجز مؤكد في هذه المرحلة.

## 5. مراحل التنفيذ

### المرحلة صفر — جمع معلومات الشركة
**الحالة:** اكتملت قائمة الخدمات وسياسة التسعير حسب النطاق؛ بقيت بيانات تشغيلية مفتوحة.
- جمع ساعات العمل، الموقع الدقيق، ووسيلة التواصل الرسمية إن أراد صاحب المشروع أن يذكرها المساعد.
- تحديد من يستقبل التحويلات البشرية وكيف تُسند المحادثة.

### المرحلة الأولى — إعداد المنصة
**الحالة:** اكتملت للتجربة.
- ربط Manus بمشروع Kapso.
- التحقق من رقم Sandbox.
- تشغيل المساعد على GPT-4.1 mini.
- لا حاجة إلى Vercel الآن.

### المرحلة الثانية — بناء المساعد
**الحالة:** مفعّل على Sandbox.
- إعداد Workflow لرسائل الوارد على Sandbox.
- ضبط الشخصية الصنعانية وقواعد الدقة والخصوصية.
- جمع ملخص طلب العميل والإحالة البشرية عند الحاجة.

### المرحلة الثالثة — الاختبار والتحسين
**الحالة:** الخطوة التالية.
- اختبار التحية والتعريف بالخدمات واستقبال طلب مشروع.
- اختبار أسئلة السعر ودوام العمل والتوفر، والتأكد أن المساعد لا يخترع إجابات.
- اختبار طلب التحدث مع موظف والتأكد من ظهور الإحالة في صندوق Kapso.
- فحص سجل تنفيذ Workflow بعد كل اختبار، ثم تحسين تعليمات المساعد.

### المرحلة الرابعة — تقييم التكاملات
- تحديد ما إذا كان حفظ Leads في CRM/Google Sheets أو إشعار الموظفين مطلوبًا.
- استخدام وظائف Kapso أو تكامل جاهز متى غطى الحاجة.
- إضافة Vercel فقط عند وجود وظيفة خادم محددة لا يغطيها Kapso، وتحديد الأسرار والبيانات التي يحتاجها قبل إنشاء المشروع.

### المرحلة الخامسة — قرار الإطلاق الحقيقي
- مراجعة الأسعار والتكلفة وسياسات WhatsApp/Meta والخصوصية.
- تحديد آلية التصعيد للموظف والرقم الحقيقي ونطاق الإطلاق.
- أخذ قرار منفصل من المالك قبل ربط رقم إنتاجي أو تفعيل الرد عليه.

## 6. قائمة اختبار مقترحة
1. «السلام عليكم، ايش خدمات كيان سوفت؟» — رد صنعاني مختصر ودقيق.
2. «أبغى موقع لمشروعي» — يسأل المساعد سؤالًا واحدًا لفهم المتطلبات.
3. «كم السعر وكم بياخذ وقت؟» — يوضح أن السعر يعتمد على النطاق، ويجمع المتطلبات دون اختلاق سعر أو مدة تنفيذ.
4. «أريد أكلم شخص من الفريق» — يستخدم مسار الإحالة البشرية.
5. رسالة غير واضحة أو خارج نطاق الشركة — يطلب توضيحًا أو يحيل بدل التخمين.

## 7. مبادئ الجودة والأمان
- عدم اختلاق الأسعار أو التوفر أو السياسات أو بيانات الاتصال.
- عدم طلب كلمات مرور أو مفاتيح API أو بيانات دفع من عميل WhatsApp.
- عدم وضع أسرار أو بيانات شخصية في GitHub أو في نصوص عامة.
- حفظ أقل قدر ممكن من بيانات العملاء، وتحديد مدة الاحتفاظ قبل الإنتاج.
- Sandbox هو بيئة الاختبار؛ الإطلاق الحقيقي يحتاج قرارًا منفصلًا ومراجعة تكلفة وسياسات.

## 8. القرارات والأسئلة المفتوحة
- **محسوم حاليًا:** استخدام GPT-4.1 mini للمساعد التجريبي؛ تجربة Gemini أُلغيت وأُعيد النموذج السابق.
- **محسوم للمرحلة الحالية:** عدم إنشاء مشروع Vercel ما دام Workflow مستضافًا في Kapso ولا توجد وظيفة خادم محددة.
- ما آلية استلام فريق كيان سوفت للتحويل البشري؟
- هل تريد حفظ بيانات الاستفسارات في CRM/Sheet؟
- ما ساعات العمل وبيانات التواصل الرسمية التي يمكن إتاحتها للمساعد؟
- هل ننتقل لاحقًا إلى رقم إنتاجي، وما النطاق والتكلفة المقبولان؟

## 9. مصدر الخطة
تستند الخطة إلى ملف تعريف كيان سوفت الذي أرفقه المالك، وإلى دليل «ChatGPT في واتسابك» الذي شرح ربط Kapso وWhatsApp. تم تكييف تجربة الحجز الواردة في الدليل لتناسب كيان سوفت: استقبال الاستفسارات التجارية وجمع موجز المشروع بدل تأكيد حجوزات لا تتوفر لها معلومات أو آلية حاليًا.
